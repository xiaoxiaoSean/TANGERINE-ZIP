# 密码压缩、解压与覆盖冲突设计

## 原生密码能力

TZIP 只生成符合相应格式规范、可被其他兼容压缩软件打开的密码压缩包，不再使用私有加密外壳。

| 格式 | 创建密码包 | 解压密码包 | 实现 |
|---|---:|---:|---|
| ZIP | 是 | 是 | SharpZipLib WinZip AES-256；SharpCompress 读取 |
| 7Z | 是 | 是 | 内嵌官方 7-Zip 组件，AES-256 并加密文件名；SharpCompress 读取 |
| RAR | 是 | 是 | 独立官方 `rar.exe` 的 `-hp`；SharpCompress 读取 |
| TAR/GZ/BZ2/XZ/LZ4/ZSTD/ISO/WIM | 否 | 不适用 | 格式标准本身没有密码字段 |

对不支持密码的格式，密码窗体会显示原因并禁用密码选项，继续创建的仍是有效、可互操作的标准文件。禁止通过改变魔数、套私有外壳或用其他格式冒充来实现“密码”。

新建密码限制为可打印 ASCII 字符。原因是 ZIP、7-Zip、RAR 及不同压缩软件对非 ASCII 密码的字节编码没有统一行为；允许这类密码会产生“创建成功但其他软件提示密码错误”的文件。压缩包内文件名仍使用 Unicode/UTF-8，不受该限制。

## 组件和单文件发布

密码 ZIP 由托管的 SharpZipLib 写入，不依赖外部程序。密码 7Z 使用 7-Zip 官方 Windows x64 23.01 发行版中的 `7z.exe`、`7z.dll`，以及原发行版随附的 `License.txt`；来源为 7-Zip 官方发行包，许可为 LGPL（`7z.dll` 另含许可文件列明的 BSD 与 unRAR 限制部分）。三者嵌入主程序，执行 7Z 密码压缩时按内容哈希释放到 `%TEMP%/TangerineZip7Zip/<hash>`。因此主程序发布结果仍只有一个 `TANGERINE-ZIP.exe`。

RAR 创建继续依赖程序目录中独立的官方 `rar.exe`，不嵌入主 EXE。`DONT_CHECK_RAR_EXE_AT_START` 只关闭启动检查，实际创建 RAR 时仍检查。

7-Zip 和 RAR 的命令行接口要求密码参数。调用使用 `ProcessStartInfo.ArgumentList`，不会经过 shell，也不会写入日志；但同一 Windows 用户在进程运行期间仍可能通过进程检查工具看到参数。密码 ZIP 没有该限制。

## 密码解压

读取 ZIP、7Z、RAR 时通过 SharpCompress 的 `ReaderOptions.Password` 传入密码。扫描到加密条目且没有密码时返回 `PWDAR0001`，认证失败返回 `PWDAR0002`，界面允许重新输入。打开阶段会把加密条目读到结尾，以触发只在流末尾执行的认证，错误密码不会被保存为当前归档密码。

加密条目先写入目标目录中的随机临时文件。只有密码和数据校验全部成功后才替换目标文件，避免错误密码、认证失败或损坏内容截断已有文件。密码只通过主进程与归档工作进程之间的 UTF-8 标准输入管道传递，不写日志。

## 覆盖冲突五选项

解压开始前不再询问统一的覆盖策略。只有实际目标文件已存在时，工作进程才通过双向 JSON 管道暂停并请求界面决定。对话框展示压缩包内条目和目标磁盘完整路径，并提供：

- 这个文件是：只覆盖当前文件；
- 这个文件否：只跳过当前文件；
- 全部是：覆盖本任务之后的所有冲突；
- 全部否：跳过本任务之后的所有冲突；
- 结束此任务：取消当前任务；右键并行批处理会取消同批次的所有工作进程。

普通归档、单文件压缩流、ISO、WIM 和 TAR 嵌套解压共用同一冲突状态机。右键多文件解压的“全部”选择跨所有并行归档生效，密码和冲突对话框使用异步门锁串行显示，避免重叠。

## 右键解压目标与进度窗

右键“解压到文件夹”固定写入 `压缩文件所在目录/压缩文件名（去掉最后一层扩展名）/`。目标目录在归档成功分析后建立。每个归档仍由独立工作进程并行处理，窗口显示汇总进度。

任务成功且没有错误时，进度窗自动关闭；发生异常或用户强制停止时保留窗口和错误信息，等待用户确认。

## StageCode

| StageCode | 含义 |
|---|---|
| `APWDW0001` | 密码为空 |
| `APWDW0002` | 两次密码不一致 |
| `APWDW0003` | 新密码包含不可互操作的非 ASCII 字符 |
| `PWDAR0001` | 原生加密归档缺少密码 |
| `PWDAR0002` | 原生加密归档密码错误 |
| `ZIPPD0001`—`ZIPPD0004` | AES ZIP 创建、输入冲突及清理失败 |
| `SZTLS0001`—`SZTLS0008` | 内嵌 7-Zip 创建、执行、释放、输入冲突及清理失败 |
| `CNFLT0001`—`CNFLT0002` | 覆盖冲突响应或处理器异常 |
| `CNFFM` | 覆盖冲突窗体模块 |

## 维护规则

不得恢复私有加密封装，不得生成魔数与扩展名不一致的文件。更换 7-Zip 二进制时必须同时更新许可文件并进行 ZIP/7Z/RAR 第三方校验。新增可加密格式前必须确认该格式存在公开且互操作的原生加密规范。
