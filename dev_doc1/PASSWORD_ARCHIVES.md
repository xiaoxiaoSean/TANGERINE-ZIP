# 密码压缩与解压设计

## 能力与兼容性

TZIP 支持为 ZIP、RAR、7Z、TAR、GZ、BZ2、XZ、LZ4、ZSTD、ISO、WIM 的创建结果设置密码，也支持解压 TZIP 创建的上述密码文件。

ZIP、RAR、7Z 存在各自的原生加密变体；TAR、GZ、BZ2、XZ、LZ4、ZSTD、ISO、WIM 的标准格式本身没有密码字段。为避免对无密码标准进行伪实现，TZIP 对所有新建密码文件采用统一的 `TZIPENC2` 加密封装。封装后的扩展名保持用户选择的格式，内部原始文件仍是标准归档，但加密后的外层文件必须由支持 `TZIPENC2` 的 TZIP 打开。未启用密码时，输出仍是可由第三方软件直接读取的标准格式。

第三方软件创建的原生密码 ZIP、RAR、7Z 通过 SharpCompress 的 `ReaderOptions.Password` 解压。是否支持某一种加密算法取决于 SharpCompress 0.50.1 的读取能力。TZIP 不会把原生密码转换为封装密码。

## 封装格式

`TZIPENC2` 使用以下参数：

- 密钥派生：PBKDF2-HMAC-SHA-256，随机 16 字节盐，600,000 次迭代，派生 256 位密钥。
- 内容加密：AES-256-GCM。
- 分块：每块最多 1 MiB，每块使用独立 nonce 和 128 位认证标签。
- 头验证：使用保留 nonce 对空明文执行 GCM 验证，错误密码会在写出任何解密内容前被拒绝。
- 关联数据：版本、原始格式、KDF 参数、原始长度以及每块编号和长度均参与认证。
- 完整性：截断、追加、块替换及认证失败均返回 `PWDAR0003`。

外层头保留原始 `FileDetector.FileType`，因此 `FileDetector` 可以在没有密码时识别用户选择的格式；该字段会在密码验证时一并认证。

## 进程与密码生命周期

密码只经主进程到归档工作进程的 UTF-8 标准输入 JSON 管道传递，不放入命令行、环境变量或日志。工作进程使用密码完成一次任务，退出后由操作系统回收进程内存。.NET 字符串不可原地清零，因此主窗体只在当前归档打开期间保存密码，并在卸载或打开其他归档时清除引用；派生出的二进制密钥通过 `CryptographicOperations.ZeroMemory` 清零。

解密后的临时归档使用 Windows `FileOptions.DeleteOnClose` 保持删除句柄。正常退出、异常退出以及强制终止工作进程都会关闭句柄并删除明文文件。目录清理失败不静默忽略，而是显示 `PWDAR0004`。创建密码归档采用“先创建标准临时归档、再加密到目标同目录临时文件、验证成功后替换”的事务流程。

原生加密条目解压时先写目标目录中的随机临时文件，密码和数据校验成功后才替换目标，避免错误密码或损坏数据截断现有文件。

## UI 与后台流程

- 创建：用户选定输出格式和位置后显示密码窗体，可关闭密码保护；启用时必须输入两次相同的非空密码。
- 打开：`TZIPENC2` 文件在扫描前询问密码；第三方原生加密 ZIP、RAR、7Z 在扫描发现加密条目后询问密码。密码错误可重新输入。
- 解压：主窗体复用当前已验证密码；Explorer 右键批量解压会为每个加密文件分别询问，并使用串行密码对话框避免多个弹窗重叠，文件处理仍保持并行。
- 所有耗时的归档、加密、解密操作均在可强制停止的工作进程中执行，并把两个阶段映射到同一条实时进度。

## StageCode

| StageCode | 含义 |
|---|---|
| `PWDFM0001` | 密码为空 |
| `PWDFM0002` | 两次密码不一致 |
| `PWDAR0001` | 缺少所需密码 |
| `PWDAR0002` | 密码错误 |
| `PWDAR0003` | 加密数据损坏、被篡改或不完整 |
| `PWDAR0004` | 临时数据清理失败 |
| `PWDAR0005` | 创建密码封装失败 |

## 维护规则

不得降低 KDF 迭代次数、重复 nonce、把密码加入进程参数、日志或异常文字。修改头结构必须增加版本号并保留旧版本读取逻辑。新增格式仍必须由 `FileDetector` 判断，禁止依据扩展名绕过内容检测。
