# 压缩包内预览与直接解压（2026-09-24）

## 界面

- 打开压缩包后，选择文件并点击顶部“预览选中的文件”，或双击该文件。双击文件夹仍进入该文件夹。
- 文字预览只读，支持鼠标/键盘选择、全选、复制、放大、缩小；水平和垂直滚动条始终可见。TXT、Markdown 等通过内容解码识别，不按扩展名猜测。
- 图片预览支持放大、缩小、左右各旋转 90°；水平和垂直滚动条始终可见。图片类型通过 `FileDetector` 的内容签名判断。两个窗口都有“另存为”。另存为输出的是原始解压字节，不会把界面上的旋转烘焙进图片；禁止覆盖来源压缩包。
- 图片初次打开时按可视区域等比缩小到完整可见，小图片不强行放大；窗口尺寸变化时，在用户手动缩放前重新适配。按住 Ctrl 滚动纵向鼠标滚轮，以鼠标所在位置为中心缩放；不按 Ctrl 时，纵向滚轮只纵向滚动。物理横向滚轮或倾斜滚轮只横向滚动，不依赖 Shift 键模拟。图片上按住鼠标左键拖动可以平移，松开或丢失鼠标捕获即停止。原有缩放和旋转按钮保留。
- 主窗口“解压”新增“解压到压缩文件所在文件夹”。此命令直接以压缩包的父文件夹为输出目录，不再弹目标文件夹选择框，也不会另外建立同名子文件夹；原有“解压到文件夹”行为不变。重名文件仍调用原来的五选项冲突窗口。若条目会覆盖当前正在读取的压缩包，则以 `MAINW0018` 阻止。

## 内存及支持范围

预览前调用 Windows `GlobalMemoryStatusEx` 读取**当前可用物理内存**，每次任务的解压字节上限设为该值的一半。若该上限不足 256 KiB，则连解码器与传输缓冲区的工作空间都难以保证，直接拒绝。已知未压缩条目长度超限时不分配；否则先为内存流分配空间，再边解压边检查真实写入字节数，防止伪造长度的压缩炸弹突破上限。GZ 等单流格式的列表长度是压缩输入长度，不能拿它当解压后长度提前拒绝，实际输出仍逐块受限。单个连续数组还受 .NET `Array.MaxLength` 限制。图片在完整解码前另外检查像素展开后的估计内存。用户可在主窗口“停止工作”取消预览读取。

ZIP、RAR、7Z、TAR、ISO、GZ/BZ2/XZ/LZ4/ZSTD，以及自动展开的单个内层 TAR，均通过内存流读取选中的一个条目，不生成临时预览文件。WIM 当前库只提供面向磁盘路径的提取接口，没有符合“只解压到内存”要求的流式入口，因此 WIM 条目预览会以 `PRVWS0004` 明确提示用户正常解压后打开，不会偷偷写临时文件。UTF-8、UTF-16（含常见无 BOM 模式）、带 BOM 的 UTF-32 及当前 Windows ANSI 代码页文字可预览；无法解码的二进制内容不会被伪装成文字。

## 异常阶段码

| 阶段头 | 用途 |
| --- | --- |
| `PRMEM` | 可用物理内存读取、无可用内存 |
| `PRVWS` | 条目读取、内存限制、格式限制 |
| `PRSVS` | 另存为、保护来源压缩包 |
| `TXPVW` | 文字窗口复制与保存 |
| `IMPVW` | 图片窗口保存、像素内存限制、缩放、横向滚轮和平移；`0003` 至 `0013` 对应各输入阶段 |
| `MAINW` | 主窗口预览入口、直接解压保护 |

新增文字已分别加入 `UiStrings.resx`（中性 en-US）、`en-US`、`zh-CN`、`zh-TW`、`zh-HK`、`zh-MO`。两个预览窗口仍使用黑底浅字、布局容器和实时鼠标效果配置。针对 ZIP 中的 UTF-8 Markdown、PNG、嵌套 TAR 条目和独立 GZip 流，已验证读出的内存字节与原始字节一致，并验证超限被拒绝；这不是完整的 GUI 或全格式实机验证。
