# TZIP 功能、顶部菜单与逻辑路径总览

整理日期：2026-10-02。代码版本：`TANGERINE-ZIP.csproj` 中的 2.1.1。

本文以当前 WPF 可执行项目的 XAML、事件处理器和服务实现为依据；菜单名称采用 `UiStrings.zh-CN.resx`。`>` 表示操作或判断的先后关系，分支单独列出。覆盖用户功能、各入口及主要内部执行、取消、异常和恢复路径，不将每一行代码展开成控制流图。

## 1. 代码范围与总体结构

| 层级 | 代码 | 职责 |
| --- | --- | --- |
| 启动 | `App.xaml.cs`、`WpfStartup.cs` | 分流证书助手、工作进程、CLI、资源管理器命令和普通 GUI；初始化配置 |
| 主窗口 | `MainWindow.xaml`、`MainWindow.xaml.cs` | 菜单、包内浏览、搜索、暂存源文件、预览、解压、压缩、编辑和拖拽 |
| 功能窗口 | 各 `*Window.xaml/.xaml.cs` | 关于、首次运行、压缩参数、密码、工具、设置、系统集成、预览与交互提示 |

| 编辑与诊断 | `ArchiveEditService.cs`、`ArchiveDiagnostics.cs` | 包内复制/移动/删除、备份、完整性检测、Hash、恢复 ZIP |

### 2.1 菜单状态规则

| 状态 | 行为 |
| --- | --- |
| 初始空窗口 | 隐藏预览、解压、卸载、暂存操作和停止工作；压缩、工具、设置等常规入口保留 |
| 暂存源文件 | 显示新建和移除；移除仅在有选中项时启用；仅一个可打开压缩包才显示打开拖动的压缩文件 |
| 已加载压缩包 | 显示预览、解压、卸载；嵌套 TAR 项按探测结果显示；清空旧暂存源 |
| 主窗口正在执行操作 | 显示停止工作；禁用打开、新建、暂存打开/移除、预览、解压、压缩、卸载和系统设置 |
| 正在准备暂存操作 | `_stagedActionPreparing` 防止重复新建、打开或移除，暂存入口被禁用 |

`SetMenuEnabled` 没有统一禁用关于、压缩包工具、设置、搜索和列表右键菜单；部分功能在处理器内再次检查忙碌状态。工具窗口有独立任务和取消令牌，不能把主窗口的停止工作视为所有窗口的全局停止按钮。

## 3. 全部功能清单与能力边界

### 3.1 格式能力

| 格式 | 打开/列出/解压 | 创建 | 密码创建 | 高级压缩 | 包内修改 |
| --- | --- | --- | --- | --- | --- |
| ZIP | 支持 | 支持 | AES-256 | 支持 | 支持普通未加密、非分卷包 |
| RAR | 支持 | 需要 EXE 同目录的 `rar.exe` | 支持数据与头部加密 | 支持 | 不支持 |
| 7z | 支持 | 支持 | 内嵌 7-Zip 工具 | 支持 | 支持普通未加密、非分卷包 |
| TAR | 支持 | 支持 | 不支持 | 不支持 | 支持 |
| GZip、BZip2、XZ、LZ4、Zstandard | 支持；普通流按一个成员显示 | 单输入流压缩 | 不支持 | 不支持 | 不支持 |
| ISO、WIM | 支持 | 支持 | 不支持 | 不支持 | 不支持 |

单文件流格式只接受一个源路径，实际编码器需要打开文件；多文件/目录内容应先组织为 TAR 等容器。底层原生库能否找到、外部工具是否存在、文件是否可访问，仍会影响实际执行结果。

`FileDetector` 还包含可执行文件、部分磁盘镜像、音视频、PDF、SQLite 等内容检测，枚举也包含 Office 类型；`ArchiveCapabilities` 才决定能否作为压缩包打开，不能把检测枚举全部视为实际检测、压缩或预览支持列表。

### 3.2 功能分组

- 基础：关于与版本信息、选择打开、启动参数打开、卸载当前包、多 GUI 实例。
- 浏览：文件夹层级、返回上级、名称/原始大小/压缩后大小、完整路径提示、多选、成员详情、全包路径搜索。
- 输入：系统文件选择器多选、文件/目录拖入暂存、暂存过滤、追加去重、移除暂存项、单包探测与打开。
- 输出：全部或选中项解压、目标同名子目录、直接解压至源包所在目录、嵌套 TAR 自动展开和手动一键解压。
- 创建：十一类归档/流/镜像格式、密码、级别/方法/字典/线程/内存/分卷选项、输出存在性确认。
- 预览：图片和文本内存预览、图片缩放旋转平移、文本全选复制/字体缩放、原始成员另存为。
- 编辑：包内复制、剪切移动、粘贴、删除、同名目标编号、重写提交和原包备份；向 Explorer 复制/剪切和拖出。
- 工具：CRC 测试、SHA-256 完整性比较、数据块读取测试、SHA256/SHA512/MD5 显示比较、损坏成员恢复、文件名编码重读。
- 设置：鼠标白色加粗效果开关/半径/厚度、五项主题颜色、各项恢复默认、临时目录设置和可用空间显示。
- 系统：首次运行可选集成、Windows 10/11 右键菜单创建删除、默认格式选择/全选/取消、自动默认关联、Windows 设置手动选择、解除注册。
- CLI：`help`、`compress`、`extract`、`list`，密码参数或环境变量、JSON 列表、冲突/异常策略、取消和退出码。
- 共用控制：进度、取消、关闭中断确认、密码重试、覆盖询问、危险路径/异常体积/成员失败交互、磁盘/内存预检、临时输出与清理、阶段代码提示。

高级设置只允许 ZIP/7z/RAR；展开后本次任务不可收回。存在零字节 `ADVANCED_MENU_ON` 时，支持高级参数的格式直接展开高级区。

参数范围：ZIP/7z 级别 0–9，RAR 0–5；字典 1–1024 MiB；线程 0–128；内存和分卷 0–1048576 MiB。线程 0 表示自动，内存/分卷 0 表示不设置限制/不分卷。方法为 Default、LZMA2、Deflate；ZIP 不允许 LZMA2，7z 不允许 Deflate，RAR 仅 Default。默认配置记录为级别 5、字典 16 MiB、线程/内存/分卷 0；具体默认引擎行为由各写入器决定。

数据块模式只验证文件能否顺序读取，不验证压缩结构或每个成员内容；CRC/恢复采用 SharpCompress 读取器，其实际格式范围不等于主窗口所有格式的能力。恢复只收集成功读取的普通文件成员，不修改原包，也不保证恢复目录空项、原格式或加密。乱码修复提供 UTF-8、GB18030、GBK/CP936、Big5/CP950、Shift-JIS/CP932、Windows-1252，改变读取解释而非重写包内文件名。

## 7. 命令行逻辑路径

CLI 在 GUI 配置初始化之前分流，不弹首次运行、密码或覆盖窗口。必要时附着调用者控制台，保留重定向输出，UTF-8 输出；不创建额外终端。命令名忽略大小写，选项名按代码要求使用小写。

| 命令 | 选项 |

```text
工作进程>覆盖冲突或安全问题>发送消息>客户端询问或使用 CLI 策略>WorkerCommand 回复>继续
工作进程>完成>返回条目/嵌套信息/备份路径或 Completed>客户端验证进程退出与完成标志
工作进程>异常>返回 StageCode/Error>客户端转换为 StageException
客户端>取消>终止工作进程及完整子进程树（包含 rar/7z）>等待句柄释放>抛出取消
客户端>协议失败/读取失败/退出异常>阶段错误>finally 清理仍存活的子进程
```

预览直接使用 `ArchiveService` 在当前进程内读取并限制内存；诊断工具直接调用 `ArchiveDiagnostics`。这两类操作不全部通过 `--archive-worker`。

### 8.2 创建引擎分流

```text
创建>资源预检>高级 ZIP/7z>内嵌 SevenZipToolService.CreateConfiguredAsync
创建>高级 RAR>外部 RarToolService.CreateAsync
创建>默认无密码 RAR>外部 rar.exe
创建>默认无密码其他格式>ArchiveService.CreateAsync
创建>默认密码 ZIP>EncryptedZipService（SharpZipLib AES-256）
创建>默认密码 7z>SevenZipToolService.CreateEncryptedAsync（头部加密）
创建>默认密码 RAR>rar.exe -hp（数据与头部加密）
创建>其他格式密码请求>能力检查拒绝
```

默认写入器：ZIP 使用 .NET ZipArchive，TAR 使用 .NET Pax TarWriter，7z 使用 SharpCompress；GZip 使用 .NET，BZip2/Zstandard 使用 SharpCompress 压缩流，XZ 使用 Joveler，LZ4 使用 K4os，ISO 使用 DiscUtils，WIM 使用 ManagedWimLib。默认解压 ZIP/RAR/7z/TAR 使用 SharpCompress，流/镜像使用相应专用解码器。RAR 创建要求 `rar.exe` 实际在 EXE 同目录，仓库的 `rar_exe/rar.exe` 路径本身不等于运行时已满足条件。

内嵌 7z.exe/7z.dll 在工具需要时释放并调用。高级 ZIP/7z 和 RAR 支持线程、分卷等参数，设置内存上限时借助 Job Object。常规创建先写临时输出再移动到最终路径；分卷工具负责将临时卷发布为目标卷并检查冲突。

