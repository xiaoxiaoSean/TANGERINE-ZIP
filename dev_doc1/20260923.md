# TANGERINE-ZIP 对话总结（截至 2026-09-23）

本文整理本次对话中用户提出的需求、后续纠错、实现决策、已报告的验证结果和仍需注意的限制。它是对话总结，不是逐字聊天记录，也不把未经核实的早期答复当作事实。路径以仓库根目录 `C:\Users\Sean\source\repos\TANGERINE-ZIP` 为基准。

## 1. 项目目标与贯穿全程的约束

项目起点是 .NET 10、C#、WinForms 的 ZIP 解压软件。用户希望它成为多格式压缩与解压工具，支持 `FileDetector.FileType` 中的以下类型：ZIP、RAR、7Z、TAR、GZip、BZip2、XZ、LZ4、Zstd、ISO、WIM。需求不只包括读取，还包括创建、解压、覆盖策略、文件名编码、实时进度、全异步执行和强制停止。

全程反复强调的工程规则如下：

- 发布后主程序必须能够作为 Windows x64 自包含的单个 EXE 运行；RAR 所需的 `rar.exe` 可以作为独立可选文件。后续 7-Zip 原生组件采用嵌入主 EXE、使用时释放的方式。
- 文件类型判断必须通过 `FileDetector` 读取内容，不可单凭扩展名判断。保存对话框所选的输出类型则使用筛选器索引映射。
- 黑色背景、浅色文字。全部用户可见文字经 `LanguageManager` 获取；语言中性值为 `en-US`，覆盖中性英文、`en-US`、`zh-CN`、`zh-TW`、`zh-HK`、`zh-MO` 六份资源。
- 变量名和代码注释使用英文，注释要详细。异常应有九位 `StageCode`：五字符模块头加四字符模块内唯一序号；展示使用 `MessageTipGenerator.GenerateTip(stageCode, exception.Message)`，展示点附近写对应代码注释。
- 耗时操作要有实时进度、异步执行和异常提示。用户允许必要的短时定向测试，但在一次右键菜单修复中曾特别要求完成后不要测试、直接结束；随后针对密码包损坏和解压去向不明，又明确需要修复，助手进行了定向验证。
- 开发资料放在仓库的 `dev_doc1` 中。测试材料曾被描述为 `test/1`；实际核查到的样本为 `testfile/1/Linux教程.pdf`。

现有总览文档是 [`README.md`](README.md)，密码、解压冲突与兼容性专题是 [`PASSWORD_ARCHIVES.md`](PASSWORD_ARCHIVES.md)。

## 3. 格式、编码与密码的最终设计

### 3.1 格式支持

通常归档操作通过 [`ArchiveService.cs`](../TANGERINE-ZIP/Services/ArchiveService.cs) 完成。ZIP、RAR、7Z、TAR、GZ、BZ2、XZ、LZ4、ZSTD、ISO、WIM 均在最初的目标范围内。RAR 创建依赖应用程序目录下独立的 `rar.exe`；其他格式使用 .NET、SharpCompress、DiscUtils、Joveler、K4os 或 ManagedWimLib 等库。GZ、BZ2、XZ、LZ4、ZSTD 属于单文件压缩流，不能像 ZIP 那样在格式内部保存多个条目及原始文件名。

中文和其他非 ASCII 文件名曾反复乱码。处理目标是 ZIP 写入时设置 UTF-8/EFS 标志，7Z 使用 Unicode 条目名，TAR 使用 PAX 路径；文件选择和后台工作进程通信同样要保留 Unicode。用户反馈过“ZIP 肯定乱码”“其他语言可能也乱码”，因此后续验证不能只让自家读取器强制 UTF-8，还需使用第三方工具检查包内真实文件名。

### 3.2 私有密码封装为何被撤销

初次实现为了给全部格式提供密码，把标准归档再套一层 `TZIPENC2`、PBKDF2 与 AES-GCM 私有封装。虽然这层可以加密数据，但文件头已不再是 ZIP、RAR 等格式自己的魔数，第三方软件无法直接列出或解压。用户把这认定为致命缺陷。相关 `PasswordArchiveService.cs` 在后续修复中删除；总结和维护时不应把该方案当作现行功能。

### 3.3 现行原生密码方案

| 格式 | 创建时的密码处理 | 解压时的密码处理 | 兼容性限制 |
|---|---|---|---|
| ZIP | [`EncryptedZipService.cs`](../TANGERINE-ZIP/Services/EncryptedZipService.cs) 用 SharpZipLib 写标准 WinZip AES-256。 | SharpCompress 的 `ReaderOptions.Password`。 | 密码包是标准 ZIP；文件名继续使用 Unicode/UTF-8。 |
| 7Z | [`SevenZipToolService.cs`](../TANGERINE-ZIP/Services/SevenZipToolService.cs) 调用嵌入的官方 7-Zip 组件，AES-256，可加密文件名。 | SharpCompress 读取。 | 7-Zip 的 EXE、DLL 和许可嵌入主程序，使用时释放到临时目录。 |
| RAR | 独立官方 `rar.exe` 使用 `-hp`。 | SharpCompress 读取。 | 缺少 `rar.exe` 时不能创建 RAR；其余操作不应受影响。 |
| TAR、GZ、BZ2、XZ、LZ4、ZSTD、ISO、WIM | 标准格式未定义通用原生密码，创建窗体禁用密码并显示原因。 | 不适用标准原生密码包。 | 不能把其他格式或私有外壳伪装成这些标准格式。 |

密码窗体要求非空密码并确认两次。新建密码被限制为可打印 ASCII 字符，是为避免不同压缩软件对非 ASCII 密码使用不同字节编码；这项限制**只针对密码，不限制中文文件名**。7-Zip 与 RAR 的命令行密码参数在进程存续期间可能被同一 Windows 用户的进程检查工具看见；[`PASSWORD_ARCHIVES.md`](PASSWORD_ARCHIVES.md) 记录了这一点。

打开原生加密包时若缺密码，返回 `PWDAR0001`；密码错误或加密数据损坏，返回 `PWDAR0002` 并允许重新输入。加密条目的读取会尽量推进到结尾，以触发只在末尾发生的认证。解压先写目标目录内的随机临时文件，成功后才替换已有文件，避免错误密码或损坏数据截断原文件。

## 4. 文件检测、TAR 嵌套与目标路径

[`FileDetector.cs`](../TANGERINE-ZIP/Tools/FileDetector.cs) 是文件类型判定的统一入口。用户明确禁止以 `.zip`、`.tar` 等后缀直接判定文件内容。单层流格式的解码结果如果是 TAR，则可识别成嵌套 TAR；ZIP/RAR/7Z 内也要逐条目检查是否为 TAR。单个内层 TAR 打开时直接展示 TAR 中的内容；如果外层包含 `aaa.tar`、`bbb.tar` 等多个 TAR，则显示多个条目，并提供选择一个或多个内层 TAR 一键解压的入口。

主窗体中的“直接解压”与“解压到文件夹”必须保持不同目标语义：前者放入用户选定目录，后者先加一层以压缩包名称命名的子目录。多个 TAR 的专用操作还会为每个 TAR 建立相应子目录。右键菜单的“解压到文件夹”在致命故障反馈后明确采用 `压缩包所在目录/压缩包名称去掉最后一层扩展名/`；例如 `aaa/xxx.zip` 的输出是 `aaa/xxx/`，并在进度窗显示完整输出路径。原来有进度却没有同名文件夹，根因之一是旧版右键流程把目标设为压缩文件的父目录，显示文字与实际路径不符。

输出路径需要先规范化并检查是否仍位于目标根目录内，阻止归档条目通过 `..` 或绝对路径逃出解压目录。覆盖策略在用户最后一次纠错后改为遇到真实目标文件冲突才弹窗，而非操作开始前统一询问。

## 5. 覆盖冲突、并行任务与进度

覆盖冲突窗体展示压缩包内条目名和磁盘目标的完整路径，提供五个选择：

1. **这个文件是**：只覆盖当前文件。
2. **这个文件否**：只跳过当前文件。
3. **全部是**：本任务剩余冲突全部覆盖。
4. **全部否**：本任务剩余冲突全部跳过。
5. **结束此任务**：取消任务；在右键多文件批处理里，应取消同批次所有进行中的归档工作。

[`ArchiveWorker.cs`](../TANGERINE-ZIP/Services/ArchiveWorker.cs) 中的工作进程以 JSON 管道向 UI 发出冲突请求，暂停等待选择，随后继续或取消。右键批量操作保持并行，但密码和冲突对话框需要串行显示，避免重叠；“全部”决定应跨同一批次生效。主窗体顶部任务执行期间显示“停止工作”，按下先告知风险、得到确认后杀掉工作进程树。进度百分比来自条目或字节累计；压缩结束应切到完成状态，不能继续显示“正在压缩”。

右键进度窗成功且没有异常时自动关闭。发生错误或用户取消时保持窗口，展示错误或取消状态，供用户查看后手动关闭。所有异常需要通过 StageCode 风格展示；不能静默吞掉清理或后台异常。

## 6. Windows 11 右键菜单与安装向导

传统 `HKCU` 注册表右键菜单只会出现在 Windows 11 的“显示更多选项”。用户多次明确指出这不满足需求，并要求真正的一级右键菜单。后来采用 `third_party/ContextMenuForWindows11` 原生扩展和 MSIX 包；包、公开证书及许可证嵌入单文件主程序，安装和移除由向导执行。向导应显示步骤进度、允许中途强制取消，并在需要的步骤向用户请求 Windows 授权。旧版 Win10 风格菜单也要能被正确清理。

右键命令覆盖：

- 解压选定的一个或多个压缩包，各自到同名文件夹；先检查所有选定项是否为受支持的压缩文件，并行处理且显示综合进度。
- 将选定文件压缩为一个由用户选择格式和位置的压缩包；密码选项遵循格式能力。
- 用 TZIP 打开单个文件；若选择多个文件，提示此操作不适用后结束。

建立右键菜单时应提醒“移动程序后必须重新建立”，用户确认后才继续；删除操作应清理本工具安装的内容。由于用户曾回滚项目并多次反馈“建立没有效果”，历史上每一次尝试不应视为最终有效，实际有效性仍要以当前运行版本和 Windows Explorer 显示为准。若 EXE 移到新位置，需要从新 EXE 重新执行建立向导，更新指向新路径的命令。

## 7. 本地化、外观、StageCode 和发布

用户要求所有窗体黑底浅字、所有文字来自 `LanguageManager`，覆盖五种指定地区文化及英文中性资源。语言差异不仅是简繁转换，还包括 `zh-TW`、`zh-HK`、`zh-MO` 的用词。`ENABLE_LIGHT` 默认 `false`，显式启用时才编译光效。代码注释和变量名应为英文。

StageCode 采用九字符规则：五字符模块头、四字符明细，例如 `F00010052`。主要模块头见 `README.md`；密码与冲突相关还有 `PWDFM`、`PWDAR`、`ZIPPD`、`SZTLS`、`CNFLT`、`WORKR` 等。错误展示使用 `MessageTipGenerator.GenerateTip`。本次对话曾明确要求在展示处以 `//F00010052` 形式注明对应码。

默认发布目标是 .NET 10、Windows x64、自包含单文件、默认不启用光效。最终密码故障修复曾发布到 `artifacts/single-file-password-fix/TANGERINE-ZIP.exe`，同目录放独立的 `rar.exe`。嵌入的 7-Zip 组件允许主 EXE 仍保持单文件发布形态。右键菜单外壳扩展相关 MSIX 已嵌入程序，但系统注册需要用户运行建立向导。

## 8. 对话中已报告的验证结果及范围

针对用户最后反馈的致命问题，助手进行了短时定向验证，并报告：

- Release 构建和单文件发布成功，编译为零警告、零错误。
