# 拖入文件创建压缩包

## 原理

未打开压缩包时，`MainWindow_Drop` 异步验证 Windows `FileDrop` 中的文件和文件夹路径，去重后追加到 `_pendingCreatePaths`。再次拖入不会覆盖原列表。`RefreshPendingSourcesList` 将待处理对象显示在主列表中；文件夹以粗体区分，悬停可查看完整路径。搜索框只过滤可见项，不改变待处理集合。

用户可多选列表项，通过顶部菜单、右键菜单或 Delete 键移除。移除只修改待处理列表，不删除磁盘文件。清空后，创建入口消失，界面恢复空窗口状态。`ProbePendingArchiveAsync` 在后台根据文件内容检测格式；仅当没有打开其他压缩包、待处理集合恰好只有一个文件且格式可打开时，显示“打开拖动的压缩文件”。此时可用顶部菜单、右键菜单、双击或 Enter 打开。新增第二个对象会立即隐藏此入口；删至只剩一个压缩包会重新检测。修订号防止较早的异步检测覆盖较新的列表状态。

点击创建菜单后，`CreateArchiveFromPathsAsync` 先用 `EnsureSourcesAvailableAsync` 异步检查路径，再调用系统 `SaveFileDialog`。用户在此选择输出目录、文件名和压缩格式，再通过原有 `CompressionOptionsWindow` 确认格式选项。压缩前再次检查路径，真正的压缩交给 `ArchiveWorkerClient.CreateAsync`；`RunOperationAsync` 显示逐项进度并提供“停止工作”取消入口。输出文件缺失会报告 `MAINW0012`，其他菜单错误用 `MAINW0027`。

若用户拖入文件后在资源管理器中删除它，点击创建时会先从待处理列表移除失效项，显示本土化提示，并停止本次创建，不打开保存窗口。若用户在保存窗口或选项窗口期间删除源对象，第二次检查同样阻止压缩。压缩开始后源对象再变化，由工作进程报告错误。未受影响的待处理项保留，用户可重新点击创建。

## 调用方式

1. 启动软件，不打开压缩包。
2. 从资源管理器拖入一个或多个文件、文件夹；列表即时显示已接受的对象。
3. 可继续拖入更多对象；可搜索、多选并用顶部菜单、右键菜单或 Delete 移除。
4. 点击顶部“创建一个新压缩文件”，在保存窗口设置名称、位置与格式。确认压缩选项；需要中止时点击“停止工作”。
5. 如果列表中只有一个受支持的压缩包，可点击“打开拖动的压缩文件”，或使用右键、双击、Enter。

原“压缩 → 选择文件”菜单也复用同一个保存与压缩方法，并检查源路径。若已打开压缩包，拖入仍按现有“卸载并打开／新窗口打开”流程处理。未打开压缩包时，压缩包同样先进入待处理列表，由用户选择将它作为源文件压缩或直接打开。手动“打开”菜单始终可用于选择其他压缩包。`MAINW0031` 至 `MAINW0034` 是拖入、检测、移除、打开的异常边界；失效源路径作为可恢复状态，以普通提示显示。
